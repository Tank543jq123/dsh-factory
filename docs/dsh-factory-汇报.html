做了什么

从「接真实事件」到「两套皮肤 + 交互面板 + 自测」，每一步都有可核对的路径。

1
宿主 session projection
src/host.js 注册 factoryTrail，折叠 turn/start, step/start, tool/call, tool/result, request/header, request/context, assistant/message, user/message, developer/message, subagent/catalog。没有真实事件时状态就是 idle，不生成动画。
2
进程事件 live 接口
POST /api/dsh-factory/live 记录 agent/pre-step（next() 后记 post-step）、agent/request、agent/turn-stopping 和 session/event 的 step/tool/model 标记；保留最近 12 条 history，客户端按序补进播放队列。
3
客户端两套皮肤
conversation.view 全屏 tab + conversation.input.dock 对话上方细条/模态；SVG 等距场景，像素/水流两套材质；工人走动/搬运/脚步阴影、活塞、齿轮、机械臂、吊钩、烟、火花、传送带滚轴、拆箱翻盖、贴标、封箱。
4
真实数据面板
点车间看职责、本 turn 事件、工具名/skill 名/MCP 端点/子代理、数据走量、配置项与环境变量位置；Skill 扫描的 4 个库名来自 ctx.skills.list()，不是写死。
5
闭环自测
3082 上跑通：普通提问「1+1」→ 2 秒；/html-report + bash → 3 秒，路线 装配→Skill→模型→MCP/工具；水主题同样跑通。控制台 0 错误；HMR 前后 PID 803317 未变。

⚠️ 风险与局限

  1. 伪 3D，不是真 3D：没有 z 排序/遮挡；极少数传送带/管线交叉用桥做视觉标记，不做几何避让。
  2. SVG 手绘，不是 32px 点阵 sprite：2× 清晰，但不是严格像素画；字体用系统字体。
  3. live pre-step 是 360ms 短轮询 + 12 条历史：极短 step 可能只在 HUD 上留下最终 phase；持久回放以 step/end 为准。
  4. MCP 端点未实测：代码支持 mcp__server__tool，但本机演示环境没有配置 MCP server，所以工具窗口是真实 bash 的 tool://local。
  5. 录屏是真实事件回放：不是录模型思考过程；播放的是 3082 上真实 turn 的 session/live 事件。
  6. 对话上方展开是模态：inline 高度会被 composer stack 裁切；触发条仍在对话上方。
